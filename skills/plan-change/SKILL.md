# Plan a change

1. Restate the requested outcome and identify what is explicitly out of scope.
2. Inspect relevant instructions and code paths. Separate observed facts from assumptions.
3. Identify the smallest useful change, affected files or components, dependencies, and meaningful risks.
4. Define observable acceptance criteria, including behavior and relevant checks.
5. Present a short ordered plan. Flag unresolved decisions that materially change the result; otherwise choose a reasonable default and state it.
6. Keep the plan proportional. Do not create a planning document for a one-line, unambiguous fix unless requested.
